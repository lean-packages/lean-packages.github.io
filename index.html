WORKFLOW

How lean packaging works

A transparent three-step process that keeps distribution archives lean without disrupting your repository or development workflow. The lean-packages tools handle inspection and configuration — you handle the release.

Handled by lean-packages

01 — Inspect

Detect development-only files and identify missing or misconfigured packaging exclusions.

Handled by lean-packages

02 — Configure

Create or update your ecosystem's native packaging exclusions to keep unnecessary files out of distribution archives.

Handled by your release workflow

03 — Ship

Build and publish a leaner distribution archive using your ecosystem's standard release workflow.

GUIDING PRINCIPLES

Why lean distribution matters

Published packages are consumed thousands or millions of times. Unintentional files waste bandwidth, slow down CI, and reveal internal repository structure.

Smaller distribution archives

Minimizes archive payload size, reducing download latency and disk consumption across CI runners, server deployments, and local development environments worldwide.

Explicit package exclusions

Helps prevent accidental publication of development artifacts, internal documentation, test data, and repository configuration.

Language-native tooling

No alien configuration formats or heavy runtime wrappers. Every tool works directly with your ecosystem’s native manifests and package manager standards.

Open-source & community-driven

Transparent, permissively licensed (MIT), and built collaboratively by developers who care about sustainable, efficient software distribution.

FAQ

Frequently asked questions

Essential answers about lean packaging, archive optimization, non-destructive workflows, and CI integration.

What is a lean distribution archive?

A lean distribution archive contains only the runtime code, build assets, metadata, and license files strictly necessary for your package to function in consumer projects or production environments. It excludes test suites, CI workflows, code quality configurations, benchmarks, developer scripts, and documentation that inflate package downloads, bandwidth costs, and node storage.

Do these tools delete files from my repository?

No. lean-packages tools never delete your source files or rewrite your Git history. They may create or update the relevant packaging configuration files to control which files are included in published distributions. Your development files remain available in your repository.

Does every language use the same exclusion mechanism?

No. Each tool follows its ecosystem's native packaging conventions rather than introducing a universal exclusion format:

  • PHP Uses Git's .gitattributes export-ignore attribute to exclude files from Composer distribution archives.
  • Rust Uses the [package].exclude field in Cargo.toml to exclude files from published Cargo packages.
  • Python Uses the uv_build backend's source-exclude and wheel-exclude settings in pyproject.toml.
  • JavaScript Uses npm's files allowlist in package.json or .npmignore rules to control which files are included in published packages.
  • Zig Uses the .paths allowlist in build.zig.zon to control which files and directories are packaged in distribution archives.

Can I integrate lean-packages into CI/CD?

Yes. Every CLI tool provides a linting or verification command that returns non-zero exit codes when unexcluded development artifacts or misconfigured packaging manifests are detected. You can easily integrate them into GitHub Actions, GitLab CI, or pre-release release scripts to automatically prevent package bloat from reaching registries.

How can I contribute to the lean-packages ecosystem?

We welcome community collaboration! You can open an issue or pull request in our GitHub organization proposing or contributing a new ecosystem tool, sharing packaging specifications, or helping expand file pattern rules and test suites across existing projects.
